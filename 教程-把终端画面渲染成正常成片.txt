把终端画面渲染成正常成片 · 教程
（比例 · 分辨率 · 字形栅格化）
================================================

播放器跑在终端里时，画面是一格一格的字符。
直接录屏、或者直接放大，出来的成片要么比例不对（人物被拉扁），
要么发糊（低分辨率硬拉）。

这份教程讲怎么把它渲染成"正常"的成片。
本项目的实测参数在第七节，可直接照抄。


一、先搞清楚：终端画面是"字符网格"，不是普通视频
------------------------------------------------
终端由 COLS 列 × ROWS 行 的等宽字符单元组成，每个单元 CW × CH 像素。
所以画面的真实像素尺寸是：

    宽 = COLS × CW
    高 = ROWS × CH
    比例 R = (COLS × CW) / (ROWS × CH)

关键：R 由"单元比例"决定，跟 16:9 没有任何天然关系。

本项目（原生栅格）：

    COLS = 197，ROWS = 59，CW = 8，CH = 16
    → 1576 × 944 像素，R = 1.6695
    16:9 的目标比例 T = 1.7778

    R ≠ T —— 原生画面比 16:9 窄 6.1%

如果这时直接把 1576×944 resize 到 3840×2160，就是把画面横向拉伸 6.1%，
圆变成椭圆、人物被拉胖。这就是"比例不对"的根源。

（V5 用的是 197×52、单元 8×16 → 1576×832，R = 1.8942，比 16:9 宽 6.5%，
 拉伸方向相反。同一个坑，两个方向。）


二、两条正路，一条死路
------------------------------------------------
正路 A：补边（pad）—— 保持比例，多出来的地方填背景色
正路 B：改单元尺寸 —— 让 R 正好等于 T，一步到位、不用补边
死路：直接 scale 到目标尺寸 —— 拉伸变形

先算清楚，再动手。想让 R = T：

    CW / CH = (T × ROWS) / COLS

例一：197 列 × 52 行，要 16:9
    CW/CH = 16×52 / (9×197) = 0.4693
    取整数像素：CW=15，CH=32 → 0.4688（误差 0.1%，肉眼不可见）
    栅格化出来 2955 × 1664，比例 1.7759 ≈ 16:9

例二：197 列 × 59 行，要 16:9
    CW/CH = 16×59 / (9×197) = 0.5324
    取整数像素：CW=17，CH=32 → 0.5313（误差 0.2%）
    栅格化出来 3349 × 1888，比例 1.7738


三、路线 A：离屏栅格化（推荐）
------------------------------------------------
不用开终端窗口。逐帧调用播放器的 performance() 拿字符屏，
再用 Pillow 把每个字符画成图块拼起来。
字形稳定、可复现、分辨率随便定。

要点：
  1. 逐格画。每个字符先画成 CW×CH 的小图，再拼成
     (COLS×CW) × (ROWS×CH) 的画布。
     不要先画小图再整体放大。
  2. 字体：等宽用 Consolas，中文用微软雅黑。
     字号要让字宽 ≈ CW；中文按 2 格宽算
     （East Asian Width 为 W / F 的字符占 2 列）。
  3. 块元素 ▀ ▄ █ 直接用矩形填充，别指望字体。
  4. 补边用播放器背景色，避免出现色块。本项目 BG = (8,13,18)。
  5. 要 4K 就按 4K 的单元尺寸重新栅格化，
     不要拿 1576×944 的图放大 —— 那只是"放大低清图"，不是重绘。

伪代码：

    for t in frames:
        screen = player.performance(t, True, term, sprites)
        canvas = Image.new("RGB", (COLS*CW, ROWS*CH), player.BG)
        for y, row in enumerate(screen.rows):
            for x, (ch, fg, bg) in enumerate(row):
                if ch not in (None, " "):
                    canvas.paste(tile(ch, fg, bg), (x*CW, y*CH))
        proc.stdin.write(canvas.tobytes())     # 直接喂 ffmpeg rawvideo

小图缓存：同一个 (字符, 前景色, 背景色) 组合只画一次，存字典复用。
一帧几万格，不缓存会慢到不能用。


四、路线 B：录真实控制台窗口（"真终端实录"）
------------------------------------------------
只有需要真实 conhost 字形 / ClearType 时才用。
思路是 **1:1 像素映射，不缩放**：

  1. 放大控制台字号，让 COLS × CW 正好等于目标宽度像素。
     例：197 列 × 13 px = 2561 px ≈ 2560，单元取 13×26。
  2. 用 ffmpeg gdigrab 抓控制台客户区（客户区坐标，不是窗口坐标）。
  3. 抓完再 pad 到目标高度补黑边，不要拉伸。

这一步的坑（都是真踩过的）：
  · 丢列：conhost 在"移动窗口 / 改字号"时会重算
    floor(客户宽 / 单元宽)，197 列很容易掉成 196 列。
    要先摆好窗口位置，再改字号；
    必要时用 SetConsoleScreenBufferSize + SetConsoleWindowInfo 强制回 197×52。
  · 屏幕不够宽：197 × 13 = 2561 > 2560，最后 1 像素会被裁。
  · DPI 缩放：脚本必须先声明 DPI 感知（SetProcessDpiAwareness），
    否则抓到的区域尺寸不对。
  · 快速编辑模式：误点一下会让控制台输出冻结，录制前关掉
    （ENABLE_QUICK_EDIT_MODE）。
  · 置顶窗口：别的置顶窗口 / 工具窗口飘进来会被录进画面，
    录制前枚举检查一遍。
  · 前摇：从启动到正式演出之间有空档，用首帧特征色定位后裁掉。


五、交给 ffmpeg 的两条命令
------------------------------------------------
补边（保持比例，推荐）：

    ffmpeg -i master.mkv -vf "pad=2560:1440:0:(1440-ih)/2:color=0x080D12" ^
           -c:v libx264 -preset slow -crf 17 -pix_fmt yuv420p ^
           -c:a aac -b:a 192k -movflags +faststart out.mp4

不要这样（会拉伸）：

    ffmpeg -i master.mkv -vf "scale=2560:1440" ...

真需要缩放时，先 pad 到同比例、再 scale，顺序不能反。
24 fps、yuv420p、faststart 是本项目的惯例，照抄即可。


六、画质要到"正常水平"的检查清单
------------------------------------------------
  [ ] 比例   量一下输出尺寸，(COLS×CW)/(ROWS×CH) 与目标是否一致
  [ ] 不拉伸 画面里的圆还是圆，字宽字高比例正常
  [ ] 字形   是重新栅格化出来的，不是把低清图放大
  [ ] 取整   CW / CH 用整数像素，避免半像素造成锯齿与抖动
  [ ] 缺字   中文有没有变成方块，逐个看生僻字
  [ ] 抽帧   首 / 中 / 末帧检查裁切、变形、黑边是否均匀
  [ ] 解码   ffmpeg -v error -i out.mp4 -f null - 全片过一遍
  [ ] 边界   解码通过不等于好看；抽帧不等于看过全片


七、本项目实测参数（照抄）
------------------------------------------------
    字符网格        197 列 × 59 行（播放器默认 197×60）
    单元（原生）     8 × 16 px
    原生画面        1576 × 944 px       R = 1.6695
    目标比例 16:9   T = 1.7778
    4K 母版         3840 × 2160（16:9）
    背景色          RGB(8,13,18) = #080D12
    帧率            24 fps
    时长            211.9067 s ≈ 3 分 32 秒
    字体            C:\Windows\Fonts\consola.ttf、msyh.ttc
    控制台录制单元   13 × 26 px（197×13 = 2561 ≈ 2560）
    两路对照        V5 用 197×52 网格；V6 用 197×59 网格

照着做，出来的就是比例正确、字形清楚的成片，
而不是一条被拉扁的终端截图。
